# Wall Concrete & Construction — Website

Marketing website for **Wall Concrete & Construction, LLC**. It is a fast static site: plain HTML, CSS and JavaScript generated by a small Node build script with **zero dependencies**, so it can be hosted anywhere.

Its design follows the four reference sites the client picked: Wollam Construction, TSJ Construction, Gerber Construction and Western Paving.

| Reference | What we took from it |
| --- | --- |
| Wollam | Full-screen hero **slideshow** with numbered slide tabs, service cards, bonding/stats call-outs |
| TSJ | Contact top bar, "Join Our Team" CTAs, swipeable project cards, careers page with benefits, open positions and application form |
| Gerber | Full-screen **background video**, big stat counters, bold condensed headlines, testimonials |
| Western Paving | "Covering all your concrete needs" service grid, numbered "Why us" cards, service detail page layout (capabilities, gallery, CTA band), "Work With Us" CTA |

---

## Quick start

Requires **Node.js 20+**. Nothing to install.

```bash
npm run dev     # build + local server at http://localhost:4321 with live reload
npm run build   # production build into ./dist
```

`dist/` is the finished website. Upload its contents to any static host.

## Editing content

All content lives in `src/data/`. You don't need to touch any HTML.

| File | What's in it |
| --- | --- |
| `site.mjs` | Company name, phone, email, address, hours, service areas, social links, stats, form endpoints, hero slides, navigation |
| `services.mjs` | Each service: name, descriptions, capabilities, FAQs, images. Add an entry and a new page is created. |
| `projects.mjs` | Portfolio entries: title, service, location, photo, scope |
| `content.mjs` | Testimonials, "why us" points, process steps, values, benefits, job openings, general FAQs |

In headings, wrap words in `*asterisks*` to highlight them in the brand accent color, e.g. `'Covering *all* your concrete needs.'`

## ⚠️ Before launch: replace the placeholders

The client didn't provide business details, so placeholders were used. `npm run build` lists the ones still present, and you can search `src/` for **`PLACEHOLDER`** to find every one.

- [ ] **Phone, email, street address, hours, service counties.** Set in `src/data/site.mjs`.
- [ ] **Domain.** Set `url` in `src/data/site.mjs`; it's used for SEO tags and the sitemap.
- [ ] **Stats.** "20+ years", "1,500+ projects" and the rest are examples. Use real numbers.
- [ ] **Testimonials.** These are written examples. Replace them with real client reviews (e.g. from Google). Do not publish invented reviews.
- [ ] **Projects.** These are sample entries illustrated with stock photography. Replace them with the client's real projects and photos.
- [ ] **Company story** on the About page (`src/pages/about.mjs`): founding year, history, owners.
- [ ] **Job openings and benefits** (`src/data/content.mjs`).
- [ ] **Social links** (`src/data/site.mjs`). Set a value to `''` to hide that icon.
- [ ] **Form endpoints.** See below.
- [ ] **Logo.** A placeholder "W" mark was designed for this build. If the client has a logo, swap it in `src/lib/icons.mjs` (`logoMark`), `public/favicon.svg` and the PNG icons.
- [ ] **Privacy policy.** A general template. Have the client review it.

## Forms (estimate requests and job applications)

The forms post to any form-handling service; no server code is needed. The recommended option is **[Formspree](https://formspree.io)** (free tier available):

1. Create two forms in Formspree, one for "Estimate requests" and one for "Job applications".
2. Paste their endpoints into `src/data/site.mjs`:
   ```js
   forms: {
     estimate: 'https://formspree.io/f/xxxxxxx',
     careers: 'https://formspree.io/f/yyyyyyy',
   },
   ```
3. For file uploads (plans, photos, resumes), make sure the form plan supports attachments.

Forms include client-side validation, a spam honeypot (`_gotcha`), drag-and-drop file upload, and an on-page success message. Until endpoints are set, submitting a form asks the visitor to call or email instead, so no leads are silently lost.

Web3Forms, Basin, Getform and Netlify Forms also work. Any endpoint that accepts a multipart `POST` and returns `2xx` will do.

## Photos & video

### Replacing photos

1. Put the new photos (JPG/PNG, ideally 2400px+ wide) in a folder.
2. Run:
   ```bash
   python scripts/optimize-images.py path/to/folder --large name1,name2
   ```
   This writes responsive WebP sizes to `public/assets/img/photos/` and records them in `src/data/images.json`. Use `--large` for images shown full-width (page heroes). Requires `pip install Pillow`.
3. Reference images by file name, without the extension, in the data files (e.g. `image: 'my-driveway'`).

**Tip:** Name a new photo the same as an existing one (e.g. `flatwork.jpg`) and every place that uses it updates automatically.

### Hero slideshow videos

The home page hero cycles through looping background videos (`hero.slides` in `site.mjs`). Each slide has a desktop file, a lightweight mobile file and a poster image. To use the client's own footage (drone shots of their jobs are ideal):

```bash
bash scripts/encode-hero-video.sh raw-footage.mov hero-driveway 12 8   # start at 0:12, 8 seconds long
```

Then add `{ label: 'Driveways', video: 'hero-driveway', href: 'services/flatwork/' }` to `hero.slides`. Requires ffmpeg.

How the hero behaves:

- Only the visible slide's video is downloaded, and the next one preloads shortly before it's needed.
- Phones get the 540p version.
- Videos pause when scrolled off screen or when the tab is hidden.
- Visitors can pause, skip or swipe through slides.
- Visitors with "reduced motion" turned on, or with data saver enabled, see still poster images instead.

## Deploying

Any static host works. Recommended: **Netlify**, **Cloudflare Pages** or **Vercel** (all free for a site this size).

| Setting | Value |
| --- | --- |
| Build command | `npm run build` |
| Output directory | `dist` |
| Node version | 20 or later |

Or run `npm run build` and upload the contents of `dist/` to any web host (cPanel, S3, etc.). If the site is served from a sub-folder instead of the domain root, set `basePath` in `site.mjs` (e.g. `'/wall/'`).

## Project structure

```
build.mjs                 Build script + dev server (no dependencies)
src/
  data/                   ← all editable content
  lib/                    templating, layout (header/footer/SEO), components, icons
  pages/                  one module per page
public/                   copied as-is into dist/
  assets/css/main.css     all styles (design tokens at the top)
  assets/js/main.js       all interactions
  assets/img/             optimized photos, video posters, logo, social share image
  assets/video/           hero + background videos
scripts/
  optimize-images.py      photo optimizer
  encode-hero-video.sh    video encoder
```

**Design tokens** (colors, fonts, spacing) are CSS variables at the top of `public/assets/css/main.css`. Change `--accent` to rebrand the whole site.

## Features at a glance

- **Hero:** full-screen video slideshow with Ken Burns motion, progress tabs, pause/play, swipe, and an auto-pause when off screen.
- **Navigation:** sticky header that turns solid on scroll and hides on scroll down; services mega menu; full-screen mobile menu; "Call / Free Estimate" bar on phones.
- **Animation and media:** scroll-reveal animations, animated stat counters, a looping video stats band.
- **Projects:** draggable project carousel, filterable portfolio (shareable `?service=` URLs), and a project lightbox with keyboard, swipe and deep links (`#project-slug`).
- **Content:** testimonial slider, animated FAQ accordions, service-area map, Google Map embed.
- **SEO:** `GeneralContractor`, `Service`, `FAQPage`, `JobPosting` and `BreadcrumbList` structured data; Open Graph / Twitter cards; canonical URLs; sitemap.
- **Accessibility:** semantic HTML, skip link, keyboard support, visible focus states, ARIA on interactive widgets, reduced-motion support, AA color contrast.
- **Performance:** responsive WebP images, lazy loading, a preloaded hero poster, no frameworks. CSS and JS are each a single file, cache-busted by content hash.
